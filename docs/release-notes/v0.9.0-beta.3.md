**Third beta of Thrum.** This one is about trust rather than new features:
an installer, no administrator prompts while Thrum runs, the VIIPER backend
reachable from this PC only, and two full code reviews plus live testing that
fixed well over a hundred problems, from crashes and hangs to lost settings.
Native PS5 mode now plays the game's own controller-speaker audio without
extra switches.

This is still a **beta**, and the list of what is *not* verified is kept as
carefully as the list of what is.

## Read this before you download

**Two downloads, the same program:**

- **`Thrum_0.9.0-beta.3_x64_setup.exe`, the installer (recommended, new).**
  Installs for all users in `C:\Program Files\Thrum` (one administrator
  prompt, while installing), or for you only without administrator rights.
  Start menu entry, an entry in Settings > Apps, and an uninstaller.
- **`Thrum_0.9.0-beta.3_x64.zip`, the portable copy.** Unzip anywhere and run
  `Thrum.exe`.

**The build is unsigned.** Windows will show "Windows protected your PC" —
More info → Run anyway. Verify what you downloaded instead of trusting the
warning either way. The SHA-256 of every download is in the table at the end of
these notes and in `SHA256SUMS.txt`:

```powershell
Get-FileHash .\Thrum_0.9.0-beta.3_x64_setup.exe -Algorithm SHA256
```

**Requires:** Windows 10/11 x64. Self-contained: you do **not** need the .NET
Desktop Runtime. Thrum now runs on .NET 10 (supported until November 2028).
ARM64 Windows is not supported: the virtual-controller driver cannot load there.

**Virtual controllers use the same driver-side components as beta 2**,
installed and verified by Thrum's setup against pinned SHA-256 digests:
usbip-win2 0.9.8.0 and this project's build of VIIPER v0.1.2
(https://github.com/potpiemuncher/VIIPER/releases/tag/thrum-v0.1.2-usbip0980.1).
If beta 2 set them up, there is nothing to reinstall.

**Do not use this alongside hbashton's DS4Windows.** Both claim the same
controller, and they need different usbip-win2 releases.

## Coming from beta 2

- **Beta 2 tells you about this release** within a day of starting it (or
  straight away with Check for updates). It opens this page; it does not
  download anything.
- **Settings carry over.** They live in `%APPDATA%\Thrum`, whichever download
  you pick.
- **Staying portable:** exit Thrum (tray icon > Exit) and extract the new zip
  over the old folder.
- **Moving to the installer:** exit Thrum, run the installer, start the
  installed Thrum once, then delete the old folder. Run at startup follows the
  installed copy the first time it starts. If HidHide is installed, the old
  folder's entry in its application list is harmless; you can remove it in the
  HidHide Configuration Client.
- **The Windows Firewall rule for `viiper.exe`.** Beta 2's backend listened on
  every network interface, and Windows asked about it the first time. This
  release listens on 127.0.0.1 only, so there is no prompt and nothing on your
  network can reach it. A rule you allowed back then no longer exposes
  anything; you can remove it in Windows Defender Firewall > Allow an app.
- **Virtual audio endpoints** (game haptics and the pad's speaker in Native PS5
  mode) are now on by default **for new installs**. A setting you saved in an
  earlier beta keeps its value: if you never turned them on, they are still off
  (Settings, or step 4 of the Native PS5 setup sheet).
- **DualShock 4 speaker users of earlier betas:** using the DS4's Bluetooth
  speaker turned Windows' USB selective suspend off for good. Thrum now puts
  it back when the speaker stops, but cannot know what an earlier beta changed.
  To restore it: Control Panel > Power Options > Change plan settings >
  Change advanced power settings > USB settings > USB selective suspend
  setting > Enabled.

## What changed

**Native PS5 mode**

- **The game's own controller audio plays without extra switches.** In beta 2,
  what a game sent to the virtual DualSense's speaker (and, over Bluetooth,
  its haptics, which travel with it) reached your controller only if
  "Stream audio to controller" was on. Now it always does in Native PS5 mode;
  that switch is only for streaming other audio to the controller.
- **Turning it on no longer loses the controller for about 25 s**; with a
  controller connected it is ready in 1–2 s.
- **The VIIPER backend listens on this PC only** (see above).
- **Audio Haptics stays off while the game drives the haptics.** Beta 2 said
  it was off but kept vibrating the controller from PC audio over Bluetooth.
- **A warning when another program had the controller first.** If Steam opened
  your DualSense before Thrum did, Thrum says so and names it. Reconnecting
  the controller fixes it.
- The card shows a green "On · game haptics via the virtual pad" instead of
  orange warnings when the audio endpoints are on.

**Everyday use**

- **No administrator prompts while Thrum runs.** Exclusive mode no longer
  relaunches Thrum elevated when another program holds the controller (it uses
  shared mode and tells you); Driver Setup opens the vendors' pages instead of
  running downloaded installers as administrator; the "Task" Run at startup
  mode is gone (an existing task is replaced by the Startup-folder shortcut).
- **Haptic feedback strength on a DualSense is shown as Level 1–8**, the
  controller's eight hardware steps, instead of a percentage that jumped after
  you let go. Speaker, microphone and Audio Haptics gain sliders move in 5 %
  steps.
- **Settings are saved crash-safely with a backup.** A damaged profile or
  Auto Profiles file is restored from its backup when the backup is good.
- **Auto Profiles:** changes you make while an auto profile is active are saved
  to that profile, not over your assigned one.
- **HidHide:** Thrum removes only the entries it added itself. Earlier betas
  could remove devices and applications you had added in the HidHide client.
- **Keys and mouse buttons** left held or toggled by a binding are released on
  a profile switch, a disconnect and Stop.
- **Importing a profile that launches a program** shows the program's path and
  asks whether to keep it.
- **The DualSense battery reading** uses the controller's own scale (80–89 %
  no longer shows 100 %), and the pad shows Charging on a wall charger.
- **The update check** no longer opens a dialog when you are offline, honours
  "Skip this version", and does not offer the release you are running.
- **After sleep**, Thrum restarts its service even when Windows woke without
  you touching anything.
- **"Play app through controller"** on a wired DualSense no longer plays about
  9 % fast.
- **RealTime process priority is removed** (it needed administrator rights); a
  saved RealTime runs as High.
- Logs are capped (10 MB per file), a crash leaves a notice instead of
  vanishing, and windows fit high-DPI screens.

**Under the hood:** crash, hang, deadlock and leak fixes across the controller,
audio, HID, UDP/OSC and VIIPER paths. The full list, with file references, is
in `CHANGES-REVIEW.md` in the repository.

## What is verified

**On real hardware** (the owner's PC: a DualSense over Bluetooth and over USB,
Native PS5 mode, Steam running, between 2026-09-26 and 2026-10-25):

- Native PS5 mode with the virtual DualSense: input, game rumble and adaptive
  triggers relayed to the pad (2,027 feedback frames in one session, none
  dropped), also with the virtual audio endpoints off.
- A 1 h 25 min play session: Thrum about 4 % of one CPU core, memory flat at
  147–153 MB, no growth in handles or threads. Idle with no controller: 0.5 %.
- The virtual DualSense's speaker plays on the controller with "Stream audio
  to controller" off; its microphone reaches Windows with the microphone switch
  on.
- Auto Profiles (switching, reverting, saving to the auto profile), Audio
  Haptics staying off in Native PS5 mode, the Level 1–8 haptic strength.
- Sleep and resume (one clean stop, one restart), controller power cycles,
  USB plug and unplug, and a clean exit that releases HidHide and stops the
  backend.
- The backend attaching over 127.0.0.1.

## What is NOT verified

- **Game-authored haptics over Bluetooth with a real game** (see above). The
  haptics data is sent; Windows' speaker "Test" sound cannot show it, because
  the controller only switches to haptics when a game asks it to.
- DualSense Edge on real hardware, and game haptics over a USB cable.
- Any controller other than DualSense on real hardware: DS4, DS3, Switch Pro
  and Joy-Con carry inherited support this beta has not re-tested.
- "Play app through controller" in Native PS5 mode (Audio Haptics stands aside
  there), a wake from sleep with no user input, signing out with Thrum running,
  OSC and the DSU (UDP) server.
- Multiple controllers at once.

## Known issues

- **After sleep, or when Thrum restarts, Steam can open the controller first.**
  Thrum then runs it in shared mode and shows the warning above. Turn the
  controller off and on to give it back to Thrum. Steam showed only the virtual
  pad in testing, so no double input was seen.
- **The Windows speaker "Test" on the virtual DualSense does not buzz the
  motors.** Expected; see above.
- **If the VIIPER backend crashes**, the controller freezes for about 40 s and
  the virtual pad is not re-created. Restart Thrum.
- Pressing Start and Stop quickly in a row, or Stop while a controller is
  connecting, can leave the service in an odd state. Restart Thrum.
- **Audio Haptics over Bluetooth** (outside Native PS5 mode) overrides the
  profile's lightbar, player LEDs and adaptive triggers while it runs.
- Two wired DualSense controllers share one haptics endpoint, and the
  microphone relay is shared between controllers.
- A DualShock 4's Bluetooth speaker can stall its input while it plays.
- Any program running on this PC can talk to the VIIPER backend's local API.
- Uninstalling leaves the VIIPER folder, its firewall rules and any HidHide
  entries behind. The installer runs on ARM64 Windows, where the driver cannot
  load.
- Carried over from beta 2: the virtual **DualShock 4** output creates speaker
  and microphone endpoints even with the audio endpoints switch off; after
  virtual controllers have been used, **uninstalling or upgrading usbip-win2
  0.9.8.0 can hang** until a reboot (reboot first); turning Native PS5 mode off
  applies on the next connection.

## Reporting problems

Use the Diagnostics page → Copy full report. It redacts your username, MAC
addresses and audio endpoint GUIDs. **Never attach a crash dump to a public
issue** — dumps contain kernel memory. If Windows blue-screens while Thrum is in
use, note the time and the stop code and open an issue with the Diagnostics
report; do not upload the dump.
